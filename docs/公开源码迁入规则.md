# 公开源码迁入规则

本文件记录仓库迁入边界，不包含私人本地路径或未公开的工程数据。

## 一、版本身份

- Steam 工坊 ID：`3636472421`
- 当前 GitHub 仓库：`apo-so/Title-MAA-Manager`
- 现有 OneDrive 本机安装快照记录：`2026.10.17.01-restore`
- 工坊当前公开包与本机安装快照的内容一致性：**尚未核实**

仓库今后若上传源码，应在提交说明中清晰注明来源版本。不可将未完成开发候选称作 Steam 正式版。

## 二、建议公开的文件

经逐项检查版权与隐私后，优先考虑：

- `common/`：本项目原创脚本及必要的自有配置
- `events/`：项目原创事件文件
- `gui/`：本项目原创或可合法再发布的界面文件
- `localization/`：项目自行编写或获得授权的本地化
- `descriptor.mod`：核对身份和路径字段后纳入
- `thumbnail.png`：确认权利归属后纳入

涉及原版界面或脚本的大面积改写文件须逐项核对游戏开发商的使用条款及第三方来源，不能仅因已放在Mod文件夹里就认定可以公开。

## 三、不得未经审查公开

- 存档、个人路径、测试录屏及含身份信息的截图
- AI交接、内部协作记录、账号信息、令牌或密钥
- 历史ZIP、开发备份、临时部署或差异审计中夹带的敏感内容
- 没有再发布授权的原版资源、第三方Mod源码及美术素材

`.gitignore`只降低误添加概率，不能替代上传前逐文件检查。

## 四、迁入与发布顺序

1. 核对 OneDrive 本机源码与目标正式发布版本的身份。
2. 逐文件筛选、检查许可证/署名、BOM与换行字节。
3. 在本地完成无敏感数据审计，再提交公开的源码。
4. 对导入版本记录文件清单、SHA-256以及变更说明。
5. 通过审查后建立源码发布标签；不要把“静态通过”描述为“游戏内验收通过”。

## 五、协作规范

- 所有开发任务和变更说明优先使用简体中文。
- 一次提交聚焦一类功能修改。
- 游戏实机结果只记录实际执行的版本、场景和证据，不虚构通过状态。
- 工坊包与GitHub仓库的发布角色不同，互不自动同步。
